# 📊 数据团队数据化管理方案

> 三个小组：**数仓（Data Warehouse）· BI（商业智能）· 数据产品（Data Product）**
> 核心理念：**用数据管理数据团队，让每个小组的产出可量化、可追溯、可优化**

---

## 一、整体架构：数据化管理三层模型

```

```

## 二、各小组指标体系

### 1️⃣ 数仓组（Data Warehouse）

> 核心职责：数据采集、ETL、数据建模、数据质量

| 维度 | 指标 | 目标值 | 数据来源 |
|------|------|--------|---------|
| **产出效率** | 每周新增/更新表数 | ≥ 5 张 | Datahub / 元数据 |
| **产出效率** | 需求平均交付周期 | ≤ 5 工作日 | Jira / 需求系统 |
| **数据质量** | 数据质量告警数/月 | ≤ 10 次 | 质量检查平台 |
| **数据质量** | 数据准确率（抽样校验） | ≥ 99.5% | Great Expectations |
| **数据质量** | SLA 违约次数（核心表延迟） | = 0 次 | 调度系统 |
| **SLA** | 核心表产出时间（每日） | ≤ 8:00 | Airflow / DolphinScheduler |
| **SLA** | ETL 任务成功率 | ≥ 99% | 调度系统 |
| **技术健康** | P0 故障数/季度 | = 0 | 故障记录 |
| **技术健康** | 复杂任务优化（耗时降低） | 季度 ≥ 3 项 | 任务耗时对比 |
| **资产覆盖** | 核心业务线覆盖率 | 100% | 数据地图 |

**数仓健康度公式：**
```
数仓健康分 = 产出效率(25%) + 数据质量(35%) + SLA达成(25%) + 技术健康(15%)
```

---

### 2️⃣ BI 组（Business Intelligence）

> 核心职责：报表开发、可视化、数据洞察、自助分析

| 维度 | 指标 | 目标值 | 数据来源 |
|------|------|--------|---------|
| **交付效率** | 需求平均交付周期 | ≤ 3 工作日 | Jira |
| **交付效率** | 每月新增报表/看板数 | ≥ 8 个 | BI 平台 |
| **使用活跃** | 日活看板用户数 | 环比增长 | BI 平台日志 |
| **使用活跃** | 报表日均访问 PV | ≥ 500 | 埋点 |
| **使用活跃** | 报表平均停留时长 | ≥ 2 分钟 | 埋点 |
| **质量** | 数据准确率（与数仓对齐） | 100% | 双向校验 |
| **质量** | 报表 Bug 数/月 | ≤ 2 个 | Bug 追踪 |
| **业务价值** | 被业务引用的报表占比 | ≥ 70% | 使用统计 |
| **业务价值** | 业务满意度评分 | ≥ 4.2/5 | 季度调研 |
| **覆盖** | 核心业务部门报表覆盖率 | 100% | 部门矩阵 |

**BI 健康度公式：**
```
BI健康分 = 交付效率(20%) + 使用活跃(35%) + 质量(20%) + 业务价值(25%)
```

**关键洞察指标（BI 组独有）：**
```
僵尸报表率 = 30天无访问的报表数 / 总报表数
→ 目标：< 15%（定期清理僵尸报表）

自助分析率 = 业务自己创建的看板数 / 总看板数
→ 目标：逐年提升（赋能业务）
```

---

### 3️⃣ 数据产品组（Data Product）

> 核心职责：数据中台产品、数据服务 API、用户画像、推荐/算法

| 维度 | 指标 | 目标值 | 数据来源 |
|------|------|--------|---------|
| **产品交付** | 版本按时发布率 | ≥ 95% | 项目管理 |
| **产品交付** | 需求吞吐量（月完成 Story 数） | ≥ 20 | Jira |
| **用户体验** | 产品 NPS 评分 | ≥ 40 | 用户调研 |
| **用户体验** | API 平均响应时间 | ≤ 200ms | APM |
| **用户体验** | API 可用性 | ≥ 99.9% | 监控 |
| **业务价值** | 数据服务调用量（日 QPS） | 环比增长 | 网关日志 |
| **业务价值** | 产品直接贡献收入/节省成本 | 季度可量化 | 业务对账 |
| **技术质量** | 线上 Bug 数/月 | ≤ 3 个 | Bug 系统 |
| **技术质量** | 需求返工率 | ≤ 10% | 需求评审记录 |

**数据产品健康度公式：**
```
产品健康分 = 交付(20%) + 用户体验(30%) + 业务价值(30%) + 技术质量(20%)
```

## 五、落地路线图

### Phase 1：基础建设（第 1-2 周）

```
✅ 确定每组 3-5 个北极星指标（不要贪多）
✅ 选定数据采集工具（Jira / Git / 调度系统 / BI 平台日志）
✅ 建一张「团队管理底表」（Google Sheet / 飞书多维表格）
✅ 人工采集第一周数据，跑通流程
```

### Phase 2：自动化看板（第 3-4 周）

```
✅ 搭建 Lead Dashboard（用你们自己的 BI 工具）
✅ 接入数据源（Jira API / Git API / 调度日志）
✅ 每周自动推送周报到群
✅ 确定告警规则（连续2天SLA违约 → 钉钉告警）
```

### Phase 3：持续优化（第 5-8 周）

```
✅ 月度复盘：指标是否合理？要不要调？
✅ 僵尸指标清理：没人看的指标直接砍
✅ 引入预测：下个月需求积压预估
✅ 季度考核数据化：评分卡上线
```

## 六、技术选型建议

| 层级 | 工具 | 说明 |
|------|------|------|
| 需求管理 | Jira / 飞书项目 | 需求、Bug、Story 全量管理 |
| 代码质量 | SonarQube / GitLab | 代码评审、技术债 |
| 数据质量 | Great Expectations / dbt test | 数仓数据校验 |
| BI 平台 | Metabase / 帆软 / Tableau | 报表 + 自助分析 |
| 调度监控 | DolphinScheduler / Airflow | ETL 任务监控 |
| 元数据 | Datahub / Amundsen | 血缘、字典 |
| 管理看板 | 直接用内部 BI | **吃自己的狗粮** 🐶 |

> 💡 **最重要的一点**：数据团队管理一定要用**自己的 BI 工具**做管理看板——既是管理工具，也是产品 dogfooding。

---

## 七、避坑指南

| 坑 | 现象 | 解法 |
|----|------|------|
| 🕳️ **指标太多** | 30 个指标没人看 | 每组 ≤ 5 个北极星指标 |
| 🕳️ **纯看数字** | 为了指标做无意义的事 | 指标只是参考，定期校准 |
| 🕳️ **只罚不奖** | 团队抵触数据化管理 | 指标用来发现问题和表扬，不是扣绩效 |
| 🕳️ **一上来就自动化** | 还没跑通就开始写系统 | 先跑 2 周人工数据，再自动化 |
| 🕳️ **忽视协作** | 各组各搞各的 | 30% 权重给跨组协作 |

---

**一句话总结：用数据管数据团队——数仓看质量和 SLA，BI 看使用和业务价值，数据产品看体验和调用——三组合力，一张看板，一个节奏。** 🎯
